# ClipCascade 3.2.0.36

Android build-toolchain maintenance release. Windows is version-aligned with no
clipboard or UI behavior changes. Server 3.2.0.33 remains compatible and unchanged.

- Android builds with Gradle 9.8.2, Microsoft JDK 25.0.4.1+1, AGP 9.3.1 and
  Kotlin 2.4.21, retaining React Native 0.80.2 and its existing architecture.
- Update the build plugin's Android DSL integration and explicitly declare the
  existing AES/PBKDF2 namespaces. Autolinking uses the installed CLI directly,
  avoiding npm 12's Windows command-shim quoting failure.
- Preserve release unit-test generation and React Native's generated resources
  across AGP 9's changed defaults. Use the supported ProGuard template while
  keeping shrinking disabled.
- Declare the existing Notifee service dependency at app compile time and keep
  the navigation-bar style correctly qualified for API 27+, preserving API 26.

## Packages

- `ClipCascade-Android-3.2.0.36.apk`: versionCode 3020036, original package/signer,
  min SDK 26, target SDK 35 and all four ABIs.
- `ClipCascade-Windows-3.2.0.36.exe`: file/product version 3.2.0.36.
- `SHA256SUMS`: hashes of both downloads.

The Android APK's 40 native libraries are byte-for-byte identical to 3.2.0.35.
Clipboard capture, encryption, application acknowledgements, retry identity,
notification grace periods and UI artwork are preserved.

## Verification

The integrated native contracts, release lint and signed Android assembly passed
through the shared build gate, with its resource profile and Gradle daemon exit
verified. Lint reports zero errors; existing warnings remain visible. Patch
application was verified against registry originals whose integrity matches the
lockfile. JS contracts and focused version/resource contracts pass.

Both local client packages passed version/hash and packaged-source checks,
including Android signer/provenance/retry guards and Windows source/artwork.
Kotlin's published fully-tested Gradle ceiling is 9.7; this exact 9.8.2 combination
was verified in ClipCascade rather than claimed as an upstream-tested pairing.

Maintenance does not automatically install Android or restart/update an installed
Windows client. Credentials, encryption keys and user data are unchanged.
