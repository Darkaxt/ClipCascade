# ClipCascade 3.2.0.35

Android and Windows reliability update. Server 3.2.0.33 remains compatible;
no server JAR or server upgrade is included.

- Unconfirmed retries retain the same delivery ID and exact encrypted message.
  A client that already applied the item re-acknowledges it without pasting again;
  a failed recipient can retry. Explicit Resend still starts a new delivery.
- Android remote clipboard writes carry a process-local provenance marker.
  Shizuku and the standard native watcher do not broadcast those writes back,
  even if JS callbacks are delayed beyond the short echo window. A fresh copy of
  identical text from another app remains eligible for synchronization.
- Windows queues a busy inbound clipboard application outside the WebSocket
  handler. It waits for native access and only acknowledges successful application.
  Newer remote data, local clipboard changes or disconnect supersede stale work;
  repeated retransmissions do not create repeated error rows or new workers.
- Windows diagnostics use bounded rotating files, preserve existing entries and
  initialize correctly even when a library configured logging first. Activity
  records contain direction/type/status, not clipboard content.
