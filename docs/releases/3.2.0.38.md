# ClipCascade 3.2.0.38

Android battery release. Windows is version-aligned with no behavior changes.
Server 3.2.0.33 remains compatible and unchanged.

- While the screen has been off for 60 s, a lost P2S connection is retried every
  5 minutes instead of every 10 s, and the stuck-connection recovery check runs
  at the same pace. The server can be unreachable for hours while the phone
  rests (for example when TailD pauses its VPN while idle), and fast retries
  would keep waking the device for nothing.
- When the screen turns on, a disconnected client reconnects at once instead of
  waiting out a retry scheduled while idle.
- The "Connection Lost" notification is not raised while the screen is idle or
  during the first 30 s after wake, while the network or VPN comes back.
- Heartbeats, clipboard capture, encryption, delivery and P2P mode are
  unchanged.

## Verification

Desktop unit tests (114) and mobile JS contracts (110, including the idle retry
policy) passed. Release unit tests, lint and the signed Android assembly passed
through the shared build gate. The APK signer matches 3.2.0.37. The Windows
package passed packaged-source verification. The read-only Windows clipboard
check could not run: another process held the clipboard open without a window
(OpenClipboard access denied), so it is recorded as not completed. Windows has no
behavior changes in this release.
