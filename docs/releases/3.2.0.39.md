# ClipCascade 3.2.0.39

Windows reliability release. Android is version-aligned with no behavior changes.
Server 3.2.0.33 remains compatible and unchanged.

- The Windows client unpacks its runtime under
  `%LOCALAPPDATA%\ClipCascade\runtime` instead of `%TEMP%`. Windows Storage
  Sense (the SilentCleanup task) deletes old files from `%TEMP%`, which removed
  the Tk/ttk scripts of a client that had been running for a while. The Control
  Room then opened as a blank window showing only the rail icon.
- If the Control Room still cannot be built, the half-built window is destroyed
  and a native error message explains how to recover. It no longer leaves an
  empty window behind.
- `tools/audit_client_health.py --probe` waits up to `--ack-wait-seconds`
  (default 5) for acknowledgements. It no longer reports clients that are still
  answering as pending.
- The release script uses the native Coordinator Gradle gate, and the packaged
  Windows check verifies the runtime location.
