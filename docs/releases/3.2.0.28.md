# ClipCascade 3.2.0.28

## Explicit Resend

Both activity views offer Resend for retained text entries, separate from local
Copy. It uses the existing encrypted P2S/P2P transport and size limits without
changing the local clipboard. This explicit action bypasses immediate duplicate
suppression, is unavailable while disconnected, and never queues offline sends.
Sent means local transport handoff, not a remote delivery acknowledgment.

## Recovery Fixes

- Windows keeps one reconnect worker through repeated DNS/TCP/STOMP failures,
  waits for STOMP CONNECTED before enabling sends, and ignores stale transport
  close callbacks. WebSocket ping/pong detects lost connections.
- Windows HTTPS uses validated OS certificate trust instead of depending on an
  expendable PyInstaller certifi file. Explicit custom CA bundles still work.
- Android discards failed STOMP transports on missed heartbeats and incomplete
  handshakes, allowing reconnect even if the native socket never reports closure.
- Android watchdog diagnostics record the current health-check phase and elapsed
  time without clipboard contents or credentials. This helps diagnose distinct
  foreground-loop stalls; their historical cause is not assumed to be identical
  to the transport defect.

- Repeated DNS failures before initial Windows connection and after a live socket
  drop recover and send successfully against a real local WebSocket/STOMP server.
- Real stompjs regression tests reproduce Android's dead-socket and silent-close
  failures with the old configuration and recover with the new configuration.
- Windows and Android JavaScript regression suites pass. Android release native
  tests and signed packaging are checked before publication.
- Local Windows is updated with its existing API/encryption configuration retained;
  a real clipboard event is detected and sent through the private production server.
- Published assets are independently downloaded and checked against SHA256SUMS,
  embedded versions, APK signer and the release source commit.

The Android update is not installed automatically. Strict Shizuku behavior and
the existing Tailscale/DNS configuration are unchanged.
