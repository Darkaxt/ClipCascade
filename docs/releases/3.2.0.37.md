# ClipCascade 3.2.0.37

Android battery release. Windows is version-aligned with no behavior changes.
Server 3.2.0.33 remains compatible and unchanged.

- In P2S mode the Android client asks the server for a 300 s STOMP heartbeat once
  the screen has been off for 60 s, and returns to the 20 s heartbeat as soon as
  the screen turns on. STOMP fixes heartbeats per CONNECT, so each change makes
  one intentional reconnect, which does not raise the "Connection Lost"
  notification.
- A 20 s heartbeat kept the cellular radio, and any VPN tunnel carrying the
  connection (for example Tailscale's peer-session keepalives), permanently
  awake while the phone was idle.
- New native bridge method `isInteractive()` reports the screen state from
  `PowerManager`. It defaults to interactive, so the 20 s behavior is kept if the
  screen state is unknown.
- Clipboard capture, encryption, delivery, retry identity and P2P mode are
  unchanged.
