# ClipCascade 3.2.0.33

Android, Windows and server update for reliable fresh-copy detection and P2S
clipboard application acknowledgements.

- Shizuku distinguishes a fresh same-content copy using Android's clipboard
  timestamp. Repeated polling is not treated as a new user copy.
- Each P2S message has a unique delivery ID. The server binds its origin and
  acknowledgers to authenticated sessions and excludes all sender-client sessions.
- Receivers ACK only after successful text/image application. Failed writes,
  rejected messages and queued file downloads cannot produce an application ACK.
  Successfully applied retransmissions can be re-ACKed without another write.
- `Delivered` requires all targeted sessions to ACK. `Sent` alone is unconfirmed.
  Unconfirmed copies remain eligible for fresh-copy/manual resend. Recipient
  connection changes invalidate cached delivered-payload suppression.
- Old clients, P2P and zero-recipient sends remain unconfirmed. They do not
  silently qualify for confirmed-delivery duplicate suppression.
- Credentials, E2E encryption, signing identity, icons and notification grace
  periods are unchanged. No automatic Android installation.

Verification: desktop and Android JavaScript regression suites, native Android
release tests/build, real authenticated server WebSocket fanout/application-ACK
integration, and server authorization/zero-recipient/ID-binding tests. Package
version/hash/source checks and production activation are recorded in the task
specification. Physical Android application-ACK verification requires installing
this release; old installed clients do not exercise that new path.

Files queued for manual download are `Available`, not clipboard-applied. No
timer-driven resend loop or offline payload storage was introduced.
