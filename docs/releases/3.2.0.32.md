# ClipCascade Windows 3.2.0.32

Windows-only maintenance release for clipboard messages arriving but failing to
apply with OpenClipboard access-denied or misleading WinError 0 errors.

- Coordinate native clipboard reads and text/image writes with one process lock.
- Guarantee CloseClipboard after a successful open, including failed writes.
- Use a valid owner window for writes and arm image suppression only on success.
- Handle temporary external clipboard contention within the existing 0.5-second
  acquisition budget; report persistent locks as clipboard busy, including the
  holder PID when identifiable.
- Keep read failures inside the watcher callback so subsequent updates still work.
- Preserve credentials, encryption, replay/deduplication, tray/window icons and
  the existing connection notification grace period.

Verified with desktop regression tests, fault-injected text/image/read failures,
and real Win32 read-only owner-window acquisition, contention/recovery and failure
cleanup. Test data was not written to the interactive clipboard. Private native
content-write isolation was unavailable because Windows denied station creation;
physical native text/image writes are not claimed as part of this test run.

Android remains 3.2.0.31 and the server remains 3.2.0.29. Their older artifacts are
not republished under this Windows-only release.
