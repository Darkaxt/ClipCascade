# ClipCascade 3.2.0.29

- Server-first visibility for authenticated P2S connections, with registered
  client identity and advertised platform/version.
- Two silent control ACK types: Client Alive responds to a session-bound probe;
  Clipboard Detected reports only local watcher type and server receipt time.
- Management-key-only GET /api/client-health and POST /api/client-health/probes,
  limited to the key owner's connections. Repeated requests reuse pending probes;
  stale/wrong-session ACKs cannot mark a replacement connection alive.
- No clipboard contents, previews, filenames or encryption keys in diagnostics.
  Probes never alter the clipboard or produce notifications/activity rows.
- Unsupported older clients are distinct from pending probes. ACK is not proof
  that another device received/applied a clipboard. P2P health is unsupported.
- Android APK, Windows EXE and server JAR are version-aligned. Existing encrypted
  clipboard transport, source exclusion, text resend and recovery remain intact.

Update Android manually to enable its control ACKs. Existing clients continue
syncing normally and appear unsupported until upgraded.
